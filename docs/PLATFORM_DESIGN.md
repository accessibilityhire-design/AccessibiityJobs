# AccessibilityJobs interface

The product serves accessibility professionals comparing real jobs, often reading long descriptions or navigating by keyboard. Use a light, readable interface with familiar job search controls. Keep the existing logo, routes, navigation names, structured data, and application destinations.

The first screen should show a clear purpose, a usable search form, and the start of actual results. Listings are rows: employer, title, location eligibility, work arrangement, employment, factual compensation, concise skills, and posting date. Never label unknown compensation “Competitive.” Do not claim verification, worldwide remote eligibility, salary transparency, or hiring urgency without supporting data.

Use Inter throughout. Body text is 14–16px with generous line height. Main headings stay around 32–40px; job titles stay 18px. Use ink text, white surfaces, pale neutral page backgrounds, and the logo's blue for links and primary actions. Controls have 6px corners; panels use 8px. Borders define groups. Avoid decorative animation, neon accents, gradient copy, animated company lists, and promotional statistics before the jobs.

Search settings live in the URL. Filter changes restart pagination; back and forward navigation restore inputs. Every word must match, with title and company matches ranked above incidental mentions. Location, arrangement, employment, seniority, date posted, and salary availability combine. Empty results and service failures require different messages.

Preserve visible labels, keyboard focus, clear loading feedback, 44px controls, mobile layouts, and reduced-motion preferences. Job details use the same visual language. Application buttons should not invite applications to expired roles.
